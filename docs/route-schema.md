# 路線資料格式 (`src/data/routes/<map>.json`)

每張地圖一個 JSON 檔,內容轉錄自艦R百科的標註地圖 (`public/maps/NewMap_<map>.jpg`, 1520×850)。
條件字串**照圖上原文(簡體)填寫**,由程式解析,不要自行改寫或翻譯。

```jsonc
{
  "id": "2-4",
  "nodes": {
    // key: 節點字母;起點固定叫 "start"。x,y 為節點圓心在圖片上的像素座標。
    "start": { "x": 262, "y": 772 },
    "A": { "x": 172, "y": 587 }
  },
  "routes": {
    // key: 出發節點。每個有出路的節點都要列;沒有出路的節點(BOSS、斷路)不列。
    // 單一路線(無分歧): [{ "to": "F" }]
    // 分歧:依圖上編號順序 (X1, X2, X3…) 排列
    "B": [
      { "label": "B1", "to": "D", "cond": "索敌≥150", "stars": 2 },
      { "label": "B2", "to": "E", "cond": "轻巡≥3", "stars": 3 }
    ],
    // 只有星星沒有條件 → 省略 cond;只有條件沒有星星 → stars 省略或 0
    "F": [
      { "label": "F1", "to": "I", "cond": "航母≤1", "stars": 1 },
      { "label": "F2", "to": "J", "stars": 3 }
    ]
  },
  // 選填:圖上寫的「擊破X點後,關閉A→B,開啟C→D」這類機制
  "flags": [
    { "id": "G", "text": "击破G点后", "close": [["C", "G"]], "open": [["C", "H"]] }
  ],
  // 選填:圖上其他文字說明(原文)
  "notes": [],
  // 必填(可為空陣列):轉錄時不確定的地方,用中文描述,供人工複查
  "uncertain": []
}
```

## 條件字串寫法

- 照抄圖上文字:`轻巡≥2`、`航母=0`、`索敌≥150`、`等级≤124`、`最低航速≤27`、`最高航速≥40`、`幸运≥125`、`旗舰战巡`
- 圖上若一條路線有多個條件(換行、`且`、`或`、`+`、`&` 等),照原文保留連接詞,例如 `驱逐≥2且轻巡≥1`
- 比較符號統一用 `≥ ≤ = > <`
- 被 `flags` 開啟的路線(圖上通常是灰色/虛化路線)仍要寫在 `routes` 裡,並加上 `"requires": "<flag id>"`;
  會被關閉的路線(圖上通常是橙/金色)加上 `"closedBy": "<flag id>"`

## 判定規則(程式實作用)

1. 對分歧點的每條路線判定條件;有一條以上滿足 → 走編號最前面的那條。
2. 全都不滿足 → 依 ★ 數當權重隨機(無 ★ 的路線權重 0)。
